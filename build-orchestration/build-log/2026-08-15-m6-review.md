# M6 — the review pass

The server landed last session with both suites green and no review. This session ran the
review: a whitebox pass over `server/src/`, then five advisers. Twenty-two findings, five
calls for the user, one of them high severity. All the code fixes are merged and both suites
are green — 667 server tests and 164 client tests, none failing and none skipped, up from 631
and 164. No client source changed.

The two paths the last session listed as reachable by no test are now both covered. The
backpressure ceiling needed a peer that stalls its reader, which turned out to be
unnecessary: driving `send` thousands of times inside a single `handleMessage` turn crosses
the ceiling, because Node does not flush queued socket writes mid-turn. The heartbeat reaper
is still exempt and still uncovered.

## The one that mattered

Every policy close in the server was advisory. `conn.close` calls `ws.close()`, which queues
a close frame and arms ws's close timer, but the receiver keeps running: `ws` emits
`message`, `ping` and `pong` with no `readyState` guard, and nothing in `server.js` checked
whether a connection had already been ejected. The outbound path *was* guarded, which is what
made this easy to miss for so long. Everything looked quiet from the server's side while the
peer kept being processed.

So a flooder closed 4003 kept being served for up to thirty seconds, and could clear its own
ban on the way, because `charge` still ran on its frames. The three-strike close was worse:
`consecutiveInvalid` resets on any accepted message, so one valid frame between every two
invalid ones defeats it forever. The binary-frame close was defeated by sending text.
Meanwhile `room.handleMessage` kept mutating canonical state and broadcasting to every other
peer, whose sockets were open and healthy.

The same root cause held the pre-hello slots. `releaseHelloWatch` ran only from the socket's
close event, so an uncooperative peer kept its slot for the full close timeout. Thirty-two
silent connections, recycled on a timer, make the room permanently unjoinable by anyone,
and no room code is needed to do it. That inverts `06-security.md`: the hello timeout, which
is listed as a defence, becomes the denial-of-service mechanism.

The fix is a flag set inside `conn.close` so every call site is covered without having to
find them all, early returns at the top of the three inbound handlers, the pre-hello slot
released at the moment of rejection, and a three-second forced `terminate` as a fallback.
The peer still receives its close code first, because M7 renders those codes as user-facing
text, so terminate has to be the fallback rather than the opening move.

Worth remembering for anyone testing this area: a conforming `ws` client refuses to `send()`
once it observes CLOSING, so a test written with the obvious client passes whether or not the
bug is present. The adversarial cases need raw socket framing.

## Decisions

**AGPL section 13 is documented now; the wire field waits for M7.** This is a server people
connect to over a network, so section 13 attaches as soon as anyone but the operator joins.
Nothing offered them source. The clean fix is a `source` URL on the `welcome` message, but
that is a protocol change, and the protocol rule is that `02-protocol.md` changes first, then
server, client and fixtures together. M7 is already opening the protocol for the real client
connection, so the field rides along there at almost no marginal cost. The README carries the
obligation in the meantime, and the repository is public.

**The repair snapshot now goes out every time.** `02-protocol.md` says a delta from a
non-controller draws `error{not-controller}` followed by a snapshot. The code deduplicated
that snapshot per `serverSeq`. The dedup was keyed on the wrong thing: what needs repairing is
the sender's optimistic divergence, which moves with every rejected delta, while `serverSeq`
by definition has not moved, because nothing was accepted. A client with two deltas in flight
after losing control got repaired for the first and left permanently wrong for the second —
rendering a stale gain, or worse a stale playhead, until the controller happened to touch
something. That is the exact divergence the application exists to prevent, so the code changed
to match the document. The amplification cost was accepted knowingly: `not-controller`
correctly does not count toward the three-strike close, and the per-connection token bucket is
the intended bound.

**The rate-limited error stays once per episode, and the document changed instead.** Read
literally, `02-protocol.md` asked for one error frame per dropped message. Answering every
dropped frame makes the limiter reply with more bytes than it receives, so exceeding the limit
would cost the server more than staying under it, and the limiter becomes the flood's
amplifier. Unlike the snapshot case, nothing diverges: the suppressed frames are repeat
notifications about a condition the client caused and has already been told about once. Two
findings that looked like the same shape resolved opposite ways, and the thing that separated
them was whether suppression left a peer silently wrong.

**IP addresses are named in the security scope rather than removed from the logs.**
`06-security.md` claimed no personal data beyond a display name while the server logged client
addresses at sixteen sites, including one line pairing an address with a name. Every one of
those is a join or abuse path where the address is the only thing identifying the source of a
flood once the connection is gone. The document was wrong, not the logging.

**The room code stays on stdout.** Moving it to stderr is the better engineering answer and
would have kept it out of a captured log stream, but `03-server.md` specifies stdout and the
plan outranks a preference. The README now warns plainly instead.

## Accepted as-is, deliberately

The validators re-check shape and type that `room.js` has already established. That looks
redundant from inside `room.js` and is not: each validator is a public, independently tested
contract, driven standalone by the fixture corpus with arbitrary malformed input, so every
guard is load-bearing for a caller that is not `room.js`.

The file headers in `server/src/` run longer than the commenting convention asks for and carry
design rationale. They are consistent across all seven files and the rationale is worth having.

Three fixtures assert the prototype-pollution key rules that one generic unknown-field fixture
already covers. Deleting test material during a review pass is the wrong instinct, and a
wire-contract corpus records intent rather than code paths.

`handleDisconnect` keeps its own inline membership check rather than calling the new
`isMember` helper next to it. Scope discipline by the implementer, correctly chosen over a
tidier diff, and a candidate for a later cleanup.

One test in `room.test.js` survives that, once renamed honestly, asserts nothing the
single-connection case does not already cover: the dedup it was written to distinguish is
gone. It stays, because what it now pins is that one connection's repair snapshot never
suppresses another's, and a room-level rather than per-connection dedup is exactly the bug
this session removed. Cheap insurance against reintroducing it.

Several tests carried names describing the dedup mechanism after it was deleted, and their
assertions still passed under the new rule. A green test named for a mechanism that no longer
exists is worse than a failing one, because it tells the next reader the behaviour is covered.
They were renamed and re-commented, with no assertion touched.

## Unresolved risk

The room code is still the only thing gating membership, handshakes are still unthrottled per
source address, and the sixteen-character floor is a readability threshold rather than an
entropy measurement. The README now states the achievable guess rate and recommends keeping
the generated UUID, which is honest but is not a mitigation. This was already slated to be
revisited at M7, when clients first connect across machines, and it should be.

The heartbeat reaper is still exercised by no test. `05-testing.md` exempts it deliberately,
and there is no injectable clock, so covering it would mean changing source to suit a test.
The backpressure ceiling, the other long-standing gap, is now covered.

`02-protocol.md` still does not fix the payload or the ordering of `roleChanged` when a
controller disconnects. The implementation sends it after `peerLeft`, so an M7 client driven
off its peer list will see a role change for an id it has already removed. Nothing is wrong
today because the document specifies neither, which is precisely why M7 should settle it
before the client depends on one reading.
